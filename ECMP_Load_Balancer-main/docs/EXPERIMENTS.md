# Experimental Setup, Dataset and Performance Analysis

## 1. Experimental setup
The default experiment uses a 4-leaf, 3-spine topology, 3 hosts per leaf, 10,000 Mbps per link, 200 generated flows, seed 42, and flow demands between 50 and 1,500 Mbps. It runs a baseline, failure of link `L1-S1`, and failure of spine `S2`. Change `data/config.json` to explore other settings.

## 2. Dataset
The dataset is generated by the simulator rather than downloaded from a real network. The seed and demand range are stored in `results/experiment_metadata.json`. Flow-level and link-level values are written to CSV files.

## 3. Performance analysis plan
After running:
1. Compare `max_utilization_pct` and `load_imbalance_max_over_mean` across rows in `results/scenario_summary.csv`.
2. Compare `affected_flows`, `rerouted_affected_flows`, and `disconnected_affected_flows`.
3. Check link-specific changes in each scenario's `*_links.csv`.
4. Use `graphs/scenario_max_utilization.png` to compare maximum utilisation and `graphs/failure_recovery.png` to compare affected/rerouted flow counts.
5. Repeat with different seeds, flow counts, spine counts, and demand ranges. Change one factor at a time when comparing experiments.

## 5. Result interpretation
A failure is handled successfully for a flow when at least one valid equal-cost path remains and the simulator assigns the flow to it. Utilisation may increase on surviving links after a failure. A disconnected flow indicates no available path under the current topology and failure event. No results in this document are claims about physical network performance.
